毎回ゼロから指示を書くのは大変です。
よく使うプロンプトを「型」にしておくと、品質がそろい、書く時間も減らせます。`（）` の部分を書き換えて、そのまま使ってください。

## 1. 基本の型

どのプロンプトも、次の4つを入れると、意図が伝わりやすくなります。

1. 役割: だれの立場で答えてほしいか
2. 目的: 何のために使うか
3. 条件: 文字数・形式・文体など
4. 材料: 対象になる文章やデータ

指示とデータは、XMLタグで区切ると混ざりにくくなります。

```markdown
<instructions>
（やってほしいことを書く）
</instructions>

<input_text>
（対象の文章を貼り付ける）
</input_text>
```

## 2. 要約

```markdown
<instructions>
次の文章を、（高校生）にもわかる言葉で要約してください。
- 3つの箇条書きにすること
- 重要な数字は残すこと
</instructions>

<input_text>
（要約したい文章）
</input_text>
```

## 3. 文章の校正

```markdown
<instructions>
次の文章を校正してください。
- 誤字脱字、文法の誤りを直す
- 意味は変えない
- 直した箇所を、「元の表現 → 直した表現」の形で一覧にする
</instructions>

<input_text>
（校正したい文章）
</input_text>
```

## 4. コードレビュー

```markdown
<instructions>
次のコードをレビューしてください。
- バグになりそうな点を、重要度の高い順に挙げる
- 読みやすさの改善案を、別に挙げる
- 修正案は、短いコード例で示す
</instructions>

<input_text>
（レビューしてほしいコード）
</input_text>
```

## 5. 調べものの整理

```markdown
<instructions>
（テーマ）について、次の形で整理してください。
1. 結論（2〜3行）
2. 根拠（出典が確認できるものだけ）
3. わからなかった点・確認が必要な点
</instructions>
```

:::tip[事実確認のコツ]
AIの回答は、そのまま信じず、重要な数字や固有名詞は公式の情報で確認しましょう。「確認できない点は、わからないと書いてください」と、あらかじめ頼んでおくと、推測が減ります。
:::

## 6. 追加で聞き返してもらう

依頼があいまいなときは、最初に質問してもらうと、やり直しが減ります。

```markdown
作業を始める前に、足りない情報があれば、最大5つまで質問してください。
```

- [ ] 指示と対象の文章を、タグで分けたか
- [ ] 重要な内容は、公式の情報で確認したか
