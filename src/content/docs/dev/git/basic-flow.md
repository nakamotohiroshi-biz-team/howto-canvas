Git（ギット）を学び始めたばかりの方が最初につまずきやすいのが、「なぜファイルを編集した後に、addとcommitの2回もコマンドを打たなければいけないのか？」「そもそもコミットとは何なのか？」という点です。

Gitの仕組みは「記念写真を撮ってアルバムに保存する流れ」に例えると驚くほど簡単に理解できます。
この記事では、Gitの基本概念と日常で使う黄金フローを初心者向けに優しく解説します。

## 1. カメラで理解するGitの4つの領域

Gitには、ファイルが保存されている場所（領域）が4段階あります。

```mermaid
graph LR
    A[1. ワークツリー<br>作業部屋] -->|git add<br>被写体を並べる| B[2. ステージング<br>撮影台]
    B -->|git commit<br>シャッターを切る| C[3. ローカルリポジトリ<br>自分のアルバム]
    C -->|git push<br>クラウドに共有| D[4. リモートリポジトリ<br>GitHub共有アルバム]
```

### 1. ワークツリー（作業ディレクトリ）
普段エディタでコードを書いたりファイルを保存したりしている「いつもの作業フォルダ」です。

### 2. ステージングエリア（インデックス / 撮影台）
次のコミット（記録）に含めたいファイルだけを一時的に並べる「カメラの前の撮影台」です。
編集したファイルが10個あっても、「今回はこの3個だけを1つの記録にまとめたい」という場合に、その3個だけを撮影台に乗せます。

### 3. ローカルリポジトリ（自分のPC内のアルバム）
あなたのパソコン内に保存された、過去の全履歴アルバムです。
シャッターを切る（commitする）と、撮影台に乗っていたファイルの状態が「1枚の写真（コミット）」としてアルバムに永久保存されます。

### 4. リモートリポジトリ（GitHub・共有アルバム）
インターネット上のGitHubにある保管庫です。
自分のアルバムの写真をアップロード（push）することで、チームメンバーとコードを共有したりバックアップを取ったりできます。

## 2. なぜ「add」と「commit」の2段階に分かれているのか？

初心者の方が最も疑問に思うのが「編集したなら直接コミットすればいいのでは？」という疑問です。

もしaddがなく、変更した全ファイルがいきなり1つのコミットになってしまうと:
- 「新機能のコード」と「ついでに直した無関係な誤字」が同じコミットに混ざってしまう
- あとから「誤字修正だけを取り消したい」と思ったときに分離できなくなる

撮影台（ステージング）があるおかげで、「今回はログイン機能のファイルだけをaddしてコミットする」「デザイン修正のファイルは次のコミットにする」というように、綺麗でわかりやすい履歴を作ることができます。

## 3. 日常で毎日使う黄金の4ステップ

日々の開発作業は、以下の4つのコマンドを順番に実行するだけで完結します。

### ステップ1: 変更したファイルを確認する
作業をひと区切り終えたら、まず現在の状態を確認します。

```bash
git status
```
赤色で表示されたファイルが、あなたが編集した（まだ撮影台に乗っていない）ファイルです。

### ステップ2: 撮影台にファイルを並べる（ステージング）
記録したいファイルを指定してステージに追加します。

```bash
# 特定のファイルだけを追加する場合
git add src/App.tsx

# 変更したすべてのファイルをまとめて撮影台に乗せる場合
git add -A
```
もう一度 `git status` を実行し、緑色（Changes to be committed）に変わっていれば成功です。

### ステップ3: シャッターを切って記録する（コミット）
撮影台に乗ったファイルたちを1枚の写真として保存します。
後から見返したときに何をしたかがわかるよう、説明メッセージを添えます。

```bash
git commit -m "feat: ログインボタンのクリック処理を追加"
```

### ステップ4: クラウド（GitHub）に共有する（プッシュ）
手元で記録したコミットを、インターネット上のGitHubへ送信します。

```bash
git push origin main
```
これでGitHub上に最新のコードが反映され、仲間からも見えるようになります。

## 4. 過去の履歴を確認する（git log）

これまでに記録したコミットの一覧を確認したいときは、以下のコマンドを実行します。

```bash
# 履歴を1行ずつ見やすく表示
git log --oneline -n 5
```

コミットハッシュ（7桁の英数字）とコミットメッセージが新しい順に表示されます。

## 5. 初心者が覚えておくと安心な基本ルール

- こまめにコミットする:
  何時間分もの大量の変更を1つの巨大なコミットにせず、「ボタンを作った」「APIを繋いだ」など、小さな単位でこまめにコミットを刻むと、トラブルが起きたときも戻しやすくなります。
- メッセージには作業内容を書く:
  「修正」「更新」だけではなく、「fix: 〇〇のエラーを修正」「feat: 〇〇画面を追加」のようにプレフィックスを付けると、チーム全員が履歴を追いやすくなります。
