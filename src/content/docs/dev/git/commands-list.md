日々の開発で頻出するGitコマンドとGitHub CLI（gh）の操作を、初心者が直感的に理解できるように「英単語の本来の意味」と「目的」ごとに整理した早見表です。
困ったときに手元で参照できるチートシートとしてご活用ください。

## 1. 英語の意味で覚える！Gitの基本コマンド

Gitのコマンドは、英語の日常会話の意味そのままです。意味を知ると一気に覚えやすくなります。

- init（イニシャライズ: 初期化する）: ここをGitで管理する部屋にする
- clone（クローン: 複製する）: クラウド上のリポジトリを手元に丸ごとコピーする
- status（ステータス: 状態）: 今どのファイルがどうなっているか確認する
- add（アド: 追加する）: 撮影台（ステージ）にファイルを乗せる
- commit（コミット: 誓約・記録する）: 撮影台のファイルを写真としてアルバムに刻む
- push（プッシュ: 押し出す）: 手元の記録をクラウド（GitHub）へ送る
- fetch（フェッチ: 取ってくる）: クラウドの最新状態を見に行く（手元のコードは変えない）
- pull（プル: 引っ張る）: クラウドの最新コミットを手元のコードに合体させる
- switch（スイッチ: 切り替える）: 作業するブランチを切り替える
- restore（リストア: 復元する）: 変更したファイルを元の状態に戻す
- stash（スタッシュ: 隠す・退避する）: 作業中の書きかけコードを一時的に預ける

## 2. 初期設定・準備

### 初回設定（PCを買ったときに1回だけ実行）
```bash
# コミット履歴に記録されるあなたの名前とメールアドレス
git config --global user.name "山田 太郎"
git config --global user.email "taro.yamada@example.com"

# 現在の設定一覧を確認
git config --list
```

### リポジトリの準備
```bash
# 今いるフォルダをGitの管理下にする（新規プロジェクト開始時）
git init

# GitHub上の既存プロジェクトをパソコンにダウンロードする
git clone https://github.com/ユーザー名/リポジトリ名.git
```

## 3. 状態確認とコミット（毎日の作業）

| コマンド | 説明 | 初心者向けワンポイント |
| :--- | :--- | :--- |
| `git status` | ファイルの状態を確認 | 何か迷ったらまずこれを打つ！ |
| `git diff` | ステージ前の変更差分を表示 | どこを書き換えたか1行ずつ確認 |
| `git diff --staged` | ステージ（撮影台）に乗った差分を表示 | コミット直前の最終チェック |
| `git add <ファイル名>` | 指定したファイルをステージに追加 | ファイル1つだけを記録したい時 |
| `git add -A` | すべての変更・新規ファイルをまとめてステージ | まとめて記録したい時の定番 |
| `git commit -m "メッセージ"` | ステージした変更をアルバムに記録 | メッセージには何をしたかを書く |

### 履歴の確認（git log）
```bash
# 履歴を1行ずつコンパクトに表示
git log --oneline

# 最新の5件だけを表示
git log -n 5 --oneline

# ブランチの枝分かれと合流をグラフィカルに表示
git log --graph --oneline --all
```

## 4. ブランチ操作（作業部屋の切り替え）

初心者へのアドバイス:
昔のGitでは `git checkout` という1つのコマンドで「ブランチ切り替え」と「ファイルの取り消し」の両方を行っていたため混乱を招いていました。
現在のGitでは、ブランチ切り替え専用の `git switch` と、ファイル復元専用の `git restore` を使うのが公式に推奨されています。

```bash
# 現在のブランチ一覧を表示（* が今いるブランチ）
git branch

# 新しい作業ブランチを作成して、すぐにそこへ移動する（一番よく使う）
git switch -c feature/login-form

# 既存のブランチ（例: main）へ戻る
git switch main

# 役目を終えた作業ブランチを削除する（マージ済みの場合）
git branch -d feature/login-form
```

## 5. リモート（GitHub）とのやり取り

```bash
# 接続されているリモートリポジトリのURLを確認
git remote -v

# GitHubの最新情報をダウンロードして手元に合体（毎朝作業前に実行）
git pull origin main

# 手元の作業ブランチをGitHubへ初めて送信する（-u で追跡設定）
git push -u origin feature/login-form

# 2回目以降の送信（-u を付けた後はこれだけでOK）
git push
```

:::tip[-u オプションの意味]
`-u` は upstream（上流）の略です。一度 `-u` を付けてプッシュすると、「手元のこのブランチは、GitHubのこのブランチとペアである」とGitが覚えるため、次回以降は `git push` と打つだけで自動的に正しい相手へ届くようになります。
:::

## 6. トラブルレスキュー＆取り消し（困ったとき）

```bash
# ファイルの編集ミスを破棄して、前回のコミット状態に元通り戻す
git restore <ファイル名>

# 誤って git add してしまったファイルを撮影台から降ろす
git restore --staged <ファイル名>

# 直前のコミットメッセージを書き直す（まだpushしていない場合のみ）
git commit --amend -m "正しいメッセージ"

# 作業中の書きかけコードを一時的にロッカーに預ける
git stash

# 預けていた作業コードを手元に取り出して作業を再開する
git stash pop
```

より詳しい取り消し手順は [作業取り消し＆一時退避（stash）完全レスキューガイド](/howto-canvas/dev/git/undo-and-stash/) を参照してください。

## 7. 日常の黄金サイクル早見表

チーム開発で毎日繰り返す標準的な8ステップです。

1. `git switch main`: mainブランチに移動する
2. `git pull origin main`: 仲間の最新の成果を取り込む
3. `git switch -c feature/my-task`: 自分専用の作業ブランチを作成して移動
4. ファイルを編集して動作確認を行う
5. `git status`: どのファイルを編集したか確認する
6. `git add -A`: 変更したファイルをステージングに追加する
7. `git commit -m "feat: 〇〇機能を追加"`: 説明文を添えて記録する
8. `git push -u origin feature/my-task`: GitHubへ送信し、ブラウザでプルリクエストを作成
